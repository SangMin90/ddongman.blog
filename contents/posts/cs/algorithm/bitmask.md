## 정의

> 비트 필드에서 비트 연산에 사용되는 데이터

## 용도

- 바이트(byte), 니블(nibble) 등 멀티 비트를 비트 연산으로 켜거나(1) 끌(0) 수 있다.
- 벡터 프로세싱(Vector Processing)에서 벡터 내 요소마다 `Predication`을 적용하여 조건에 맞는 요소만 연산이 실행하는데 사용된다.

## 비트 연산

### ① `NOT`

이진수 $x_{(2)}$의 각 비트에 논리적 부정을 적용하여, $x_{(2)}$ 값의 1의 보수를 만드는 단항 연산

```
NOT 0111 (십진수 7)
  = 1000 (십진수 8)
```

### ② `AND`

길이가 동일한 이진수를 입력받아 대응되는 각각의 비트 쌍에 대한 논리 연산으로, 두 비트 모두가 `1`이면 `1`, 그렇지 않으면 `0`의 결과를 얻는다.

```
    0101 (십진수 5)
AND 0011 (십진수 3)
  = 0001 (십진수 1)
```

따라서 특정 위치의 비트가 어떤 상태(_set_(`1`)인지 _cleared_(`0`))인지 확인하는데 사용할 수 있다.  
예를 들어, 이진수 $0011_{(2)}$가 주어졌을 때, 두 번째 비트가 어느 상태를 갖는지 `AND` 연산을 통해 알 수 있다.

```
    0011 (십진수 5)
AND 0010 (십진수 2)
  = 0010 (십진수 2)
```

`AND` 연산의 결과가 `0`이 아니므로 두 번째 비트는 _set_(`1`) 상태임을 확인할 수 있다.

또한 레지스터의 특정 `flag`(또는 비트)를 _clear_ 하는데 사용될 수 있다.  
예를 들어, 이진수 $0110_{(2)}$가 주어졌을 때, 세 번째 `flag`만 *clear*으로 설정할 수 있다.

```
    0110 (십진수 6)
AND 1011 (십진수 11)
  = 0010 (십진수 2)
```

이러한 특성 덕분에 첫 번째 비트 값을 확인하여, `패리티(*parity*)`(정수가 짝수인지 홀수인지 나타내는 속성)를 쉽게 확인할 수 있다.  
`x & 1`의 결과값이 `0`이면 짝수, `1`이면 홀수이다.

```
    0110 (십진수 5)
AND 0001 (십진수 3)
  = 0000 (십진수 0)
```

`AND` 연산 결과 `0`이므로 `2`로 나누어 떨어져 `짝수`이다.

집합론에서의 교집합과 동일한 개념이다.  
 ![교집합](/images/INTERSECTION.png)

### ③ `OR`

길이가 같은 두 비트 패턴을 각 비트 위치에서 비교하여, 두 비트 모두 `0`이면 `0`을, 그렇지 않으면 `1`을 반환하는 포괄적 논리합 연산

```
    0101 (십진수 5)
 OR 0011 (십진수 3)
  = 0111 (십진수 7)
```

`OR` 연산은 레지스터의 특정 비트를 _set_(`1`) 상태로 전환할 수 있다.  
 예를 들어, 이진수 $0010_{(2)}$가 주어졌을 때, 네 번째 `flag`를 *set*으로 설정할 수 있다.

```
   0010 (십진수 2)
OR 1000 (십진수 8)
 = 1010 (십진수 10)
```

집합론에서의 합집합과 동일한 개념이다.  
 ![합집합](/images/UNION.png)

### ④ `XOR`

같은 길이의 두 비트 패턴을 각 비트 위치에서 비교하여, 두 비트가 다른 값이면 `1`을, 그렇지 않으면 `0`을 반환하는 배타적 논리합 연산

```
    0101 (십진수 5)
XOR 0011 (십진수 3)
  = 0110 (십진수 6)
```

`XOR` 연산은 레지스터의 특정 비트를 _토글(toggle)_ 하기 위해 사용된다. 비트가 어떤 상태이더라도 `1`과 `XOR` 연산을 수행하면 상태가 *전환(invert)*된다.
예를 들어, 비트 패턴 $0010_{(2)}$가 주어졌을 때, 두 번째와 네 번째 `flag`를 다음과 같이 *토글*할 수 있다.

```
    0010 (십진수 2)
XOR 1010 (십진수 10)
  = 1000 (십진수 8)
```

이러한 특성은 자기 자신과 `XOR` 연산(`x XOR x`)을 통해 레지스트의 값을 `0`으로 설정할 때 최적화 기법으로 사용된다. `0` 값을 로드해서 레지스트에 저장하는 것보다 더 적은 클럭 사이클과 메모리를 요구하기 때문이다.

집합론에서의 대칭차집합과 동일한 개념이다.  
 ![대칭차집합](/images/SYMMETRIC_DIFFERENCE.png)

### ⑤ `Bit shifts`

`Bit Shifts(이하 시프트)` 연산에서는 일련의 비트들을 _오른쪽_ 또는 *왼쪽*으로 이동한다.

시프트 연산은 다음의 용도로 사용된다.

#### 비트 주소 지정(Bit addressing)

레지스터의 크기가 가장 작은 주소 지정 단위인 *바이트*보다 크다면, 시프트 연산을 통해 주소 지정 방식을 비트 단위로 더 세밀하게 관리한다.  
컴퓨터가 메모리에 데이터(숫자)를 지정하는 순서를 *엔디언(endian)*이라고 하며, 빅 엔디언과 리틀 엔디언으로 구분된다.

- **리틀 엔디언 (Little-endian)**  
  리틀 엔디언은 낮은 숫자가 낮은 주소에 지정되며, 오른쪽 자릿수부터 먼저 읽는다.  
  따라서 8자리 왼쪽 시프트는 바이트 주소를 1만큼 증가시키며, 오른쪽으로 8자리 시프트하면 바이트 주소가 1만큼 감소한다.
- **빅 엔디언 (Big-endian)**  
  빅 엔디언은 높은 숫자가 낮은 주소에 지정되며, 왼쪽 자릿수부터 먼저 읽는다.
  8자리 왼쪽 시프트는 바이트 주소를 1만큼 감소시키며, 오른쪽으로 8자리 시프트하면 바이트 주소가 1만큼 증가한다.

#### 산술 시프트(Arithmetic shift)

_산술 시프트(고정 시프트)_ 에서는 양쪽 끝에서 시프트되어 나가는 비트는 버려진다.
왼쪽 산술 시프트에서는 0이 오른쪽에 삽입되고, 오른쪽 산술 시프트에서는 부호 비트가 왼쪽에 삽입되어 피연산자의 부호를 유지한다.

```
    00010111 (십진수 23) << 1
  = 00101110 (십진수 46)
```

```
    10010111 (십진수 -105) >> 1
  = 11001011 (십진수 -53)
```

오버플로우(overflow)되지 않는 이상, n만큼 이동하는 왼쪽 산술 시프트는 $2^{n}$ 만큼 곱하는 것과 같으며, n만큼 이동하는 오른쪽 산술 시프트는 $2^{n}$ 으로 나누고 내림하는 것과 동일하다.  
이진수를 1의 보수로 처리하는 경우, n만큼 이동하는 오른쪽 산술 시프트는 $2^{n}$ 으로 나누고 올림하는 결과가 나온다.

#### 논리적 시프트(Logical shift)

*논리적 시프트*는 시프트 과정에서 버려지는 비트 자리를 무조건 `0`으로 채운다. *산술 시프트*와 달리 숫자의 부호를 유지하지 않는다.  
따라서 오른쪽 논리 시프트는 부호 비트를 복제하지 않고, `0`을 삽입하기 때문에 부호가 없는 이진수 산술에 적합하다.

#### 순환 시프트(Circle shift)

_순환 시프트_ 연산은 Carry Flag(이하 캐리 플래그) 포함 여부에 따라 크게 두 가지 방식으로 나뉜다.

#### 일반 회전(Rotate)

시프트 과정에서 캐리 플래그 없이 비트를 버리지 않고 데이터 안에서만 회전시킨다.  
이는 기존의 모든 비트를 유지해야될 때 유용하며, 디지털 암호화에 자주 사용된다.

#### 캐리를 통한 회전(Rotate)

시프트 과정에서 새로 입력되거나 출력되는 비트를 캐리 플래그에 저장하여 데이터를 회전 시키는 순환 시프트의 일종이다.  
비트를 오른쪽으로 한 칸 회전시키는 연산인 `RIGHT-ROTATE-THROUGH-CARRY-BY-ONE`는 캐리 플래그를 미리 설정해 두면, 다른 시프트 연산을 실행할 수 있다.
예를 들어 캐리 플래그에 0이 있다면 *논리적 오른쪽 시프트*이며, 부호 비트의 복사본이 있으면 *산술적 오른쪽 시프트*가 된다.  
즉, 하나의 회전 명령으로 여러 시프트 연산을 수행할 수 있기 때문에, 저사양 PC에서 비용 문제로 주로 사용한다.  
또한 프로세서의 `WORD` 크기(32비트 가정)보다 더 큰 숫자(64비트 또는 128비트)를 시프트할 때, 여러 레지스터에서 비트들이 이동하기 때문에 다른 레지스터로 이동 전에 임시 저장하는 용도로 유용하다.

## 비트마스크 함수

### Masking bits to `1`

- 특정 비트를 켜기 위해 `OR` 비트 연산을 사용한다.  
  하나의 비트 `Y`가 있다고 가정할 때, `Y OR 1 = 1` 이다.
- 예시
  ```
       10010101
    OR 11110000
     = 11110101
  ```

### Masking bits to `0`

- 비트를 끄기 위해 `AND` 비트 연산을 사용한다.
  하나의 비트 `Y`가 있다고 가정할 때, `Y AND 0 = 0` 이다.
- 예시
  ```
      10010101
  AND 00001111
    = 00000101
  ```

### Querying the status of a bit

- 일련의 비트가 있다고 가정할 때, 특정 위치에 있는 비트의 상태를 조회하기 위해 사용한다.  
  예를 들어, $100101014_{(2)}$의 네 번째 비트가 켜져 있는지 여부를 `AND` 연산을 통해 확인할 수 있다.
- 예시
  ```
      10010101
  AND 00001000
    = 00000000
  ```

### Toggling bit values

- 비트의 값을 반전(토글)시키기 위해 `XOR` 연산을 사용한다.
  하나의 비트 `Y`가 있다고 가정할 때, `Y XOR 1 = ~Y` 이다.
- 예시
  ```
      10011101
  XOR 00001111
      10010010
  ```

### Merging bits

- 레지스터의 일부분만 새로운 데이터로 덮어쓸 때 사용한다.
- 다음의 식으로 표현된다.  
  $destination = (destination ∧ ~mask) ∨ (source ∧ mask)$
  ```
  destination = (destination & ~bitmask) | (source & bitmask);
  ```

## 알고리즘에서 활용도

### 방문 체크

- 방문 표시: `mask | (1 << i)`
- 방문 취소: `mask & ~(1 << i)`
- 방문 여부 확인: `mask & (1 << i)`

### DP의 메모이제이션

동적 계획법에서 부분 문제의 결과값을 저장할 때, 해당 문제가 어떠한 상태에 있었는지 표현하기 위해 사용된다.  
예를 들어, N개의 도시를 최소 거리로 모두 순회한다고 가정하면, 1, 2, 3번 도시를 방문한 상태, $2^{1} + 2^{2} + 2^{3} = 14$ 에서 최소 거리를 DP[14]에 저장하는 방식이다.  
방문 여부를 저장하기 위해 `Map`과 같은 자료구조를 사용하는 것보다 `int` 하나만을 기준으로 상태를 표시하고, 인덱스 접근을 통해 속도도 더 빠르기 때문에 사용된다.
